## Required behavior

1. Add bounded paginated `GET /idx/{name}/chunks` and `GET /idx/{name}/chunks/{id}`. The current path has only POST/DELETE. Support useful source/ref/path/tag/date filters and explicit archived visibility. Deterministic pagination with documented consistency: stable key cursor or versioned snapshot cursor; never collect/export the entire index in each HTTP request and slice in memory. Validate limits/cursors, escape all SQL predicates, return correct 404/400, and omit vectors. The actual pinned lancedb API is 0.37.1 / Arrow 58; inspect installed crate sources if needed rather than inventing ordering features.
2. Add stable manual-memory create/detail/edit/history routes. Identity must not depend on mutable text. Each edit has expected revision, actor attribution, timestamp, content/tags, increments revision atomically and rejects stale revisions with 409. Preserve revision history. Do not bulk-delete by provenance to update a single memory. Keep old POST chunks semantics unchanged; explicit adoption of a legacy source=manual chunk is acceptable if tested and documented, but imported content is never silently rewritten as manual. Limit text/tags/annotation sizes and validate empty values.
3. Pin/unpin, archive/restore and annotations are curation metadata. Define deliberate target semantics: manual target by stable ID; imported content by explicit stable source/document identity (`source`, `ref`, `path`, with original chunk/span/revision retained as context). A changed source document must not lose its annotations/curation or silently attach one chunk's correction to unrelated content. Expose scope in API responses. Imported original text is read-only; corrections are linked annotations or source edits. Pins are not relevance scores.
4. Scoped forget preview and commit: require an explicit nonempty selector, return affected count and bounded sample, then require the exact revision/version/confirmation token to commit. For imported document/source scopes persist a suppression rule before deleting/hiding search rows so later reindex cannot resurrect them. Do not delete source files. Manual deletion can tombstone the stable record/history according to documented policy. Test stale preview, concurrent ingestion, empty selector and cross-index isolation. Preview is read-only. Legacy bulk DELETE remains compatible and documented as its existing one-time behavior unless an explicit additive suppression option is supplied.
5. Durable writes and indexing. The service already depends on bundled rusqlite; a small transactional curation database under the existing data directory is appropriate for revisions/annotations/suppressions/outbox. Preserve the LanceDB schema unless migration is necessary. Treat text+revision history as authoritative durable state; failed embedding/index projection must be visible as pending/failed, recoverable on restart and idempotently replayable. Never report fully indexed success when only memory state changed, and never claim saved data after a failed durable write. A small bounded replay step in existing maintenance is enough; no general scheduler. Per-index or per-target locking must prevent ingest/forget/edit races and resurrection. Reject or serialize legacy destructive paths where they race the new APIs.
6. Apply archived/suppressed filtering to all search/browse projections (including old search endpoints) and at ingestion write boundaries. Pins/annotations survive restart/reindex. Current ingestion `sources::write_docs` replaces rows by source/ref/path; use that document identity for durable overlays. New manual IDs must not be overwritten by old content-derived insertions. Deleting/recreating an index handles its curation state deliberately and cannot leak old records into the new namespace. mem0 remains undeletable.

For browser-compatible caller JWTs use a configured trusted validation path consistent with the existing edge/Sigiled policy; any integration with later B1 must be explicit. Never introduce unauthenticated curation endpoints or make a static bearer available to the browser. If validated human attribution cannot yet be wired, expose the limitation truthfully and keep the supported trusted actor boundary narrow.
