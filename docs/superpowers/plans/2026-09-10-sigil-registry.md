## Contracts and constraints

1. **Additive manifest.** Keep `[workspace] dockerfile`, `[app]`, `[jobs]`, `[compose]`, old `mgr.toml` fallback, and empty manifests valid. Add optional `[project]` (`display_name`, `description`), `[ide]` (enabled default true, provider default `code-server`), `[memory]` (enabled default true, documentation sources, sharing default private/project), and a small optional `[service]` descriptor. Separate IDE settings from `[workspace]`; never require an IDE Dockerfile to parse old repos. Validate names/lengths/relative source paths; reject traversal, absolute paths, unknown unsafe modes, and malformed supported fields. Never silently honor a remote memory source or arbitrary gateway target. Source-code enrollment and mem0 sharing remain opt-in.
2. **Inherited versus observed.** Every registry project has dashboard/activity/pending/workspace/IDE/memory *desired* capabilities, even before its mirror is available. Enabled/desired does not mean ready. Expose `pending`, `ready`, `disabled`, `failed` (or a similarly small documented set) per subsystem, plus desired revision, observed revision/time, safe error code/message, and retry information. Until the IDE/memory adapters exist, report `pending` with a specific reason; do not fabricate ready resources. Old snapshots deserialize with safe defaults. Existing project sharing policy must never be overwritten by a default introduced here.
3. **Idempotent registry refresh.** Registration and startup enqueue reconciliation; a bounded periodic repair loop refreshes manifest/head and capability projection. It performs no project session opens or app/job starts. Use A1's project mirror lock for all mirror read/reset/fetch sequences. Do not add another scheduler for jobs/research. Existing job manifest refresh should call the shared update path or avoid producing divergent project metadata. Record repository or manifest failure visibly; retain last known valid descriptors with stale/error metadata, and remove a declaration when a valid newer manifest deliberately removes it. Retry after outages without duplicating projects, service entries, or provisioning records. Persist only when needed; persist honest attempt/error timing. Recover pending/failed steps after restart.
4. **Dynamic services.** Built-in `catalog.json` remains the seed and keeps its current public schema/fields and status filtering. A validated `[service]` is an explicit publication of service-discovery metadata; document that distinction from private project metadata. Merge dynamic declarations deterministically. Built-in/reserved names cannot be overridden; conflicting project declarations are errors for the involved projects and cannot be resolved by last-write-wins. Dynamic names must not claim platform/auth/gateway endpoints. Restrict service endpoints to explicit valid HTTPS origins under the configured stack domain (no userinfo, query, fragments, alternate ports or arbitrary URL targets); use the typed service name/declared app relationship and configured route policy. Do not send any credential to these URLs in this task. Include optional versioned capabilities with known operation-discovery/health/UI routes, each a validated relative path, while preserving all old clients' fields. Status from declaration is a declaration, not a probe result. No secret values, environment mappings, commands, or private project text in the public catalog.
5. **Overview.** Add authenticated `GET /sigiled/overview` and `GET /sigiled/projects/{project}` (or `/overview` suffix if necessary; record exact route) using an explicit redacted projection. Root response has observed time, counts, bounded/paginated projects, and a bounded attention list. Project detail has metadata, inherited capabilities, setup status, repository revision if known, merge debt, safe A1 session views, app summary, job definitions/results, and bounded/paginated activity. Do not serialize internal SessionRecord or full build logs/job commands/secrets. Show declared app without a deployed AppRecord as not deployed/unknown, not healthy. Deployed revision, repository revision and image are separate fields; prefix-match abbreviated app SHA to full repository SHA correctly before declaring drift. Job definitions without runs are 'not run', not successful. Any cached runtime probes include timestamp and unavailable/stale/unknown state. Prefer cached projections with cheap bounded probes in the reconciler; request handlers do not perform Git operations or unbounded N-per-project network calls. Reads do not touch workspace activity.
6. **Attention.** Derive stable source references for merge debt, session failure/unprotected state, incomplete/failed provisioning, failed latest job/build, and revision drift. A healthy later job clears an older failed-run attention item. Distinguish warning/stale/unknown from failure. No inferred TODOs and no inference calls. SDE attention and explicit revisioned work items come later; leave typed extension seams, not fake records. Overview pagination deterministic (stable order and validated bounded limit/cursor or offset), project absence 404, malformed query 400/422. Avoid data loss or leaking through stringly-typed errors. Metadata access follows existing project-read permissions; mutations keep existing authorization.
7. **Compatibility.** Keep `/projects` array shape and legacy catalog compatible. Additive fields are okay. Old serialized project structs/import fixtures remain loadable; adjust tests deliberately without inventing data. Configurable feature readiness must truthfully explain browser/IDE/memory not configured. Tests should not depend on machine environment secrets or network.

## Grounded implementation map

A1 implementation interfaces (reported at 85a1ff1; parent will send final review acceptance/fixes): `SessionState::session_lock(id)` then `merge_lock(project)`; `SessionState::binding_safe(record)`; `AppState::try_persist()` returns an error, while legacy `persist()` only logs it. Use the fallible method for new state transitions. `SessionRecord::view(runtime)` is currently private: factor this safe projection into crate visibility rather than serializing raw records, which contain tokens. `Lifecycle` is Creating/Active/Recycling/Closing/Failed; errors are fixed safe `Failure` enums. Completed sessions are removed and recorded in events. Root `/sessions` envelope is `{sessions:[...]}`. Recycle now returns a generation-specific endpoint. Preserve those contracts.

Review-fix interface at c45ea77: runtime names/endpoints are compact `vm-s-{id}-g{generation}` / `/s/s-{id}-g{generation}/`; Runtime session naming helpers now take explicit generation. `Runtime::session_image_locked(project,repo,OwnedMutexGuard)` moves the mirror guard into blocking work and returns `(ImageChoice, OwnedMutexGuard)`. Any new blocking reconciliation work must also own its mirror guard while it can outlive the awaiting request. Never repeat the cancelled-future/released-lock defect.

- `ProjectRecord` previously has only name/template_version/template_behind/needs_merge; `Registry::insert` currently blindly pushes a Vec and `refresh` updates only template fields. Add uniqueness/replay behavior deliberately.
- `main.rs` AppState and StateSnapshot hold registry, events, sessions, apps, jobs, approvals. Avoid raw serialization in the new response. A1 may add persistence/locking interfaces: use those.
- `jobs::scheduler_tick` currently reads master manifests every ~300s and calls `registry.refresh`; app `status` currently performs a live Docker inspection and returns build log_tail. New overview must not blindly call the existing status handler for every row.
- `events::EventLog` has per-project `LogEntry {at_epoch,event}`; events contain session/job lifecycle only. Add paginated projection without changing their old API.
- `AppsState::dump()` has safe core metadata plus unsafe log tails. `JobsState::dump()` has latest 20 per job plus arbitrary detail. Project flags must come from current source state, not old event text.
- `catalog::serve` currently embeds/parses `catalog.json`; `/services` is public by design. A `State<AppState>` extractor is an additive wiring change.
