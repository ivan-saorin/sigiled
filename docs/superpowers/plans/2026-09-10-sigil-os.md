# Sigil OS Implementation Plan

> For agentic workers: use subagent-driven-development for independent implementation tasks with review after each. Continue unattended under the operator's 2026-09-10 approval.

**Goal:** deliver the approved modular browser operating environment while preserving existing machine clients and project work.

**Architecture:** Sigil owns projects/workspaces; SDE owns research; ADHD ideates; Genie executes models; memory stores recall. A browser driver and typed service adapters expose their existing roles through one project registry.

**Tech stack:** existing Rust/axum services, Authentik, existing edge proxy, Git-backed disposable workspaces, code-server as full IDE provider, browser UI using versioned service APIs.

**Spec:** `sigil-os-blueprint.md`, approved by the operator on 2026-09-10.

## Global constraints

- Preserve existing machine API authentication and caller JWT pass-through.
- Never expose workspace tokens, provider keys, or driver credentials in browser responses or logs.
- Session work must survive failed flush/push and container interruptions.
- New projects appear automatically; dynamic registration must not require a frontend/control-plane rebuild.
- Human and agent workspaces are distinct sessions/branches.
- Memory preserves provenance and source-derived records; corrections must survive reindexing.
- No deployment is reported complete without live verification.
- The live workspace API is the authorized code-edit/test/commit path. Isolated session branches substitute for local Git worktrees.
