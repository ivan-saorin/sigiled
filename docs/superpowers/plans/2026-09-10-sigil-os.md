# Sigil OS Implementation Plan

> For agentic workers: use subagent-driven-development for independent implementation tasks with review after each. Continue unattended under the operator's 2026-09-10 approval.

**Goal:** deliver the approved modular browser operating environment while preserving existing machine clients and project work.

**Architecture:** Sigil owns projects/workspaces; SDE owns research; ADHD ideates; Genie executes models; memory stores recall. A browser driver and typed service adapters expose their existing roles through one project registry.

**Tech stack:** existing Rust/axum services, Authentik, existing edge proxy, Git-backed disposable workspaces, code-server as full IDE provider, browser UI using versioned service APIs.

**Spec:** `sigil-os-blueprint.md`, approved by the operator on 2026-09-10.

## Global constraints

- Preserve existing machine API authentication and caller JWT pass-through.
- Never expose workspace tokens, provider keys, or driver credentials in browser responses or logs.
- Session work must survive failed flush/push and container interruptions.
- New projects appear automatically; dynamic registration must not require a frontend/control-plane rebuild.
- Human and agent workspaces are distinct sessions/branches.
- Memory preserves provenance and source-derived records; corrections must survive reindexing.
- No deployment is reported complete without live verification.
- The live workspace API is the authorized code-edit/test/commit path. Isolated session branches substitute for local Git worktrees.

## Stage A: foundation

- [x] A1: independent session runtime identities, lifecycle locking, failure preservation, legacy compatibility, safe session list/detail. Focused executable brief: `work/foundation-brief.md`. Tests cover concurrent opens, target isolation, failed flush, legacy ambiguity, and redaction.
- [x] A2: additive project metadata/capability declarations and observed provisioning state. Keep old manifests valid; merge built-in and project service descriptors with duplicate/reserved-name validation. Reconcile after registration, refresh, and restart. Tests use old/new/malformed manifests and restart replay.
- [x] A3: authenticated aggregate overview with redacted session, app/job, template/image, and provisioning states. Reads never open workspaces. Test unavailable/stale dependencies and pagination.

## Stage B: browser shell and existing service adapters

- [ ] B1: browser-originator login with server-held compatible Authentik token, host-only secure cookies, CSRF/origin checks, and capability-aware controls. Verify both human requests and unchanged machine clients.
- [ ] B2: responsive dashboard/project views backed by aggregate APIs. Implement accessible loading, empty, stale, error, and pending states. Verify keyboard navigation and real live data.
- [ ] B3: SDE research list/detail/stages/resume/handoff and Genie status/usage adapters. Preserve engine ownership, caller delegation, token expiration, and observed-versus-complete usage semantics. Use contract fixtures plus bounded live read checks. Execute as B3a (SDE persistence/run contracts) then B3b (browser adapters); inspected persistence and resume races must be addressed before browser retries are safe.

## Stage C: inherited full IDE

- [ ] C1: pinned code-server runtime layer and supervised process in a project session, retaining the project's image/toolchain.
- [ ] C2: authenticated session-specific browser origins and WebSocket routing, with server-side token custody and revocation on generation change.
- [ ] C3: commit/push/checkpoint/finish integration, failure preservation, persistent editor profile, and real activity accounting. Verify human IDE and agent coexistence through two independent sessions.

## Stage D: memory UI and accepted research

- [ ] D1: paginated chunk/index inspection and stable manual-memory revisions, provenance links, pin/archive/restore, and scoped forget preview. Test conflicts, pagination, suppression/reindex behavior, and legacy clients.
- [ ] D2: browser recall/curation interface using the common login/adapter contract. Verify search, browse, manual edits, and ingestion errors with controlled records.
- [ ] D3: automatic project namespace/documentation enrollment and accepted SDE handoff indexing. Preserve existing sharing choices; replay enrollment idempotently after outages.

## Stage E: integrated rollout

- [ ] Verify actual supervisor/edge/SSO deployment interfaces and prepare reversible release artifacts.
- [ ] Apply staged additive changes with backups and feature flags, only through authorized deployment surfaces.
- [ ] Verify create → dashboard → research → handoff → IDE → commit/close → memory, plus unchanged machine workflows.
- [ ] Write a morning review with exact commits, test evidence, live URLs, completed scope, and remaining blockers. Distinguish tested code, merged code, and deployed behavior.

Detailed task briefs are produced at each stage from the then-current code so function signatures and test cases are grounded in the implementation. They are recorded with the progress ledger, and review covers the actual diff.
