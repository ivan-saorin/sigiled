# Accepted project Memory enrollment (D3)

Source implementation; not deployed. Release Sigil and Memory together with the trusted transport and issuer configuration below. An accepted Git commit is not an indexed Memory receipt.

## Registration and recovery

The existing project registry descriptor owns `memory_enrollment`; there is no second project registry. Repository creation immediately records the existing registration event, an unpredictable persistent owner, and `registration_pending` before key generation/installation. A key failure leaves a visible partial project. Retrying the same name repairs setup with the original owner/event and incumbent key. Successful registration, normal close, and machine/browser IDE finish can schedule enrollment using the original caller JWT after their lifecycle locks have been released.

The descriptor retains a monotonic signed-i64 decimal revision, current accepted commit, bounded desired snapshot, actor, attempts, last safe error, retry hint, last confirmed receipt, and verified research handoff receipts. A new accepted commit advances the revision and replaces the desired content snapshot. GET overview/status does not write or replay work. After restart or token expiry, use authenticated Retry; no credential is persisted or acquired for a background worker. `retry_at` is an advisory diagnostic, not a perpetual retry scheduler. Bootstrap authentication cannot enroll.

Intent persistence must succeed before contacting Memory. A failed save freezes the in-process intent as `persistence_uncertain`; the validator rejects it. A successful master push followed by journal failure preserves the session and handoff marker for normal-close recovery instead of discarding acceptance evidence. Recovery reads the actual accepted repository again and persists the receipt before cleanup. Capacity failures likewise preserve the session for operator repair.

## Snapshot and ownership contract

Machine GET/POST `/projects/{project}/memory-enrollment` projects status/retries. POST `/projects/{project}/memory-enrollment/namespace` selects a deterministic separate namespace only for an unclaimed collision. Browser equivalents are below `/browser/api/projects/` with the existing session, Origin, role and CSRF checks. Normal project names remain the default namespace; matching names never prove ownership. Existing unrelated namespaces and `mem0` cannot be adopted. A deleted claimed namespace retains its generation tombstone and needs explicit operator recovery, not an old replay or silent replacement. Renaming does not migrate data.

Memory GET/POST `/idx/{namespace}/enrollment` implements `sigil-accepted-v1`. Its snapshot fields are `project`, canonical GitHub `repository` (`owner/repo`), persistent `owner`, decimal `revision`, exact accepted `commit`, sorted unique `documents` (`path,text,sha`), and explicit `shared`. SHA is SHA-256 of the exact UTF-8 content. The snapshot digest is SHA-256 of the shared typed DTO serialization, recomputed from received content and metadata. It is not a caller's asserted digest label.

Sigil collects only tracked regular UTF-8 blobs from its verified canonical repository's published master. Defaults are README.md/README.rst and documentation under docs with md/rst/txt extensions, including the operational log. Explicit manifest `memory.sources` restricts exact paths or prefixes. Code requires both selected paths and `source_code=true`; setting that flag alone does not expand default paths. Hidden paths, traversal, symlinks, submodules, NUL text, session-only/untracked research and oversized batches are rejected. A large repository must select a smaller approved set; there is no silent truncation. Disabled enrollment sends no content.

Stable D1 document identity remains source `git`, canonical repository ref, and relative path. Commit/content SHA are separate provenance. Existing annotations, archive state and permanent imported suppression survive accepted updates. Chunk IDs beginning `e_` identify this transport's rows. These documents are not registered as legacy Git ingesters. D2 Reindex explicitly directs them to authenticated project Retry, never the legacy Git fetch path.

## Trusted validation and lock ordering

Memory must advertise `enrollment_contract=sigil-accepted-v1`, `enrollment_validation=fixed_sigil_current_intent_v1`, and configured OIDC verification before Sigil sends a new write. Memory first verifies the original token with its existing fixed trusted daemon verifier. It then posts the same token and bounded proof to `/memory/enrollment/validate` on that exact verifier origin. Configure `MEMORY_AUTH_VERIFY_URL` with its required `/auth/verify` path; preserve both bare daemon routes on this internal authority. No arbitrary callback URL, redirects, proxy or substitute credentials are accepted. Callback timeout is five seconds, connection timeout two seconds and response bound 16 KiB.

Set Memory's exact trusted issuer list using `MEMORY_AUTH_ISSUERS` (comma-separated, at most eight entries, each at most 2048 bytes); it supersedes compatible `MEMORY_AUTH_ISSUER`. Verify the actual driver and browser issuers, audience, subject and Memory service policy at deployment. Same subject under different issuers remains different attribution. A desired setting does not prove live verification.

The read-only Sigil validator rechecks the actual registry owner, namespace, canonical remote and current published master against its durable snapshot/digest. The outbound enrollment holds no project/session lock. Memory holds the existing D1 mutation gate across callback and its SQLite revision CAS/projection ownership. After callback it atomically rejects stale revisions, changed ownership/body and deleted generations; a delayed successful callback cannot overwrite a newer write, and an older first request cannot be accepted merely because Memory was empty. Detached task ownership survives HTTP cancellation. Local durable outbox projection can recover already accepted work without replaying authentication or acquiring credentials.

## Bounds and retention

The exact encoded request is at most 1,100,000 bytes, at most 64 documents, 524,288 UTF-8 bytes per document and 4096 bytes per path. Sigil retains only the latest content snapshot per project, with a global maximum of 10,000 enrollment descriptors and 32 MiB for their combined serialized state, including metadata and handoffs. Each project retains at most 256 accepted handoff receipts; no silent eviction occurs. These are bounds on D3 additions, not a replacement retention policy for legacy registry state.

Memory retains one latest snapshot per namespace, including tombstoned ownership, with at most 10,000 rows and 32 MiB of actual UTF-8 serialized body bytes. Document path history is at most 4096 paths per namespace, 100,000 globally and 32 MiB of UTF-8 path bytes. SQLite enforces byte limits using BLOB lengths, not text character counts. Exceeding bounds rolls back ownership/outbox changes before projection. Existing D1 annotation/history retention remains unchanged. Review selected documents or perform an explicitly designed migration when capacity is reached; do not purge ownership or suppression to make space.

## Browser and accepted research

Project Memory says “Memory setup pending”, “Sign in to retry”, “Project only”, or “Shared with general Memory”. Project only controls propagation; it adds no per-human ACL. Explicit `sharing="mem0"` propagates accepted documents into existing general Memory without claiming it or replacing unrelated records. Changing sharing to Project only or disabling enrollment stops future propagation; existing shared copies remain subject to their existing curation controls. Namespace deletion hides its enrolled rows through the common projection filter; physical shared rows can remain until a separate approved maintenance policy removes them.

Verified namespace links require a matching confirmed owner/receipt. Source detail additionally checks fresh capability and Memory ownership against the registry, exact imported document identity/content SHA, canonical repo and accepted ancestry. Edit source uses C2's existing authenticated project-file launch; C2 checks actual file readiness and reports moved/missing/setup failures. Indexed commit and current accepted commit are separate; current checkout is checked on launch. Last confirmed indexing can become stale while the service is unavailable.

Research remains pending after bundle generation or session push. Normal close verifies both reviewed docs/design Markdown blobs, the handoff commit's ancestry and the published accepted commit before saving project/run/accepted-commit identity. Its durable receipt survives session cleanup. The browser reports master acceptance and current matching document indexing separately.

## D3 review fix 1

Source-edit authority refreshes independently of preserved source text and annotation drafts. Failed or missing detail revokes the action. Deliberate Edit source fetches the exact selected index/document again, compares owner/project/path with the observed association, and launches only the current verified target. Changed or unavailable association fails closed until a fresh deliberate action. C2 project/path authorization remains a separate check.

Ingestion status resolves the effective persisted enrollment namespace (`namespace` or project), so collision-corrected names show their own setup and unrelated original slugs do not. The shared reindex guard applies only to mem0, never arbitrary same-repository indices. Memory remains authoritative for retained shared-document protection after future propagation stops.

Memory now persists bounded indexed per-target document authority separately from the latest snapshot. Retained mem0 copies keep their exact accepted commit/content SHA/revision/owner/project/namespace and deterministic enrollment operation (the validated typed snapshot digest), with one version per target/document. The Memory curation detail/browse response exposes `accepted_provenance`; this field is stored acceptance evidence, not proof inferred from caller labels. D1 overlays/suppression and generation deletion checks remain in force. Text-free authority metadata is bounded to 100000 rows and 32 MiB of summed UTF-8 non-projection text fields plus a reserved seven-byte projection state and eight-byte present-state integer per row; this includes retained and no-longer-present path records. Capacity rejection rolls back before ownership/projection. No historical full content snapshots are added. Visibility uses indexed target/repository/path/SHA/projection metadata and never decodes full snapshot bodies per candidate.

Do not reconstruct missing historical shared provenance from a newer project-only snapshot. D3 remains unreleased; any pre-fix experimental rows without authority metadata are not verified legacy records to adopt and require original accepted evidence/explicit repair. A project-only transition is rejected while a prior shared snapshot's projection is incomplete, preserving that accepted content/outbox for recovery before propagation stops.

D3 review fix 2 reconciles the Edit source busy flag for the same still-live view after a newer same-selection Refresh, independently of the obsolete click epoch. Stale click-time detail still cannot replace current association or launch C2; only the newer verified association can make the control usable.
